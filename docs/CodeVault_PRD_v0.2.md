# CodeVault PRD v0.2

版本：v0.2  
状态：开发中（Round 1–2 已实现，其余轮次待开发）
目标：基于 v0.1 的实际使用反馈，完成一次以“可用性、导航、笔记体验、AI体验、视觉质量”为核心的升级。

---

# 1. 产品定位

CodeVault 是一个 Local-first 的 LeetCode 算法知识管理 Chrome 插件。

它不替代 LeetCode，也不提供在线判题，而是在用户刷题过程中提供：

- 题目收藏
- 多版本解法保存
- 个人笔记与图片记录
- 收藏题目管理
- 一键跳转题目
- 历史解法加载
- AI 解法分析

v0.2 的核心目标是：

> 让用户能够在“收藏题库 ↔ 当前题目 ↔ 解法 ↔ 笔记 ↔ AI分析”之间自然切换，而不被插件本身打断。

# 2. v0.1 当前问题

## 2.1 缺少主界面与返回导航

当前在具体 LeetCode 题目中，插件只展示当前题目信息。

问题：

- 无法返回收藏题目列表
- 无法快速切换到其他已收藏题目
- 插件像“当前题目工具栏”，还不像一个完整知识库

## 2.2 UI 视觉质量不足

当前问题：

- 信息密度偏高
- 层级不够明确
- 卡片、按钮、标题风格不统一
- 缺少“主界面 / 题目详情 / 设置”之间的视觉体系
- 与 LeetCode 页面结合感较弱

v0.2 需要统一设计语言。

## 2.3 笔记交互不自然

当前使用 Markdown 源文本输入。

问题：

- 普通用户看到 Markdown 符号会增加理解成本
- 图片粘贴后显示为代码或链接
- 必须点击“预览笔记”才能看到最终效果

v0.2 应改为：

> 直接输入文字 + 图片原位显示

用户不需要理解 Markdown。

## 2.4 缺少“插件页面 ↔ LeetCode页面”联动

当前收藏题目与网页之间是割裂的。

目标：

- 在插件主界面点击某题
- 当前 LeetCode 标签页自动跳转到该题
- 插件同时切换到该题详情
- 返回插件主界面后可以继续选择其他题目
- 选择其他题目时，LeetCode 页面同步跳转

## 2.5 AI配置过于技术化

当前需要用户自行配置 URL、Model 等字段。

v0.2 改为 Provider 预设：

- DeepSeek
- OpenAI / ChatGPT
- Anthropic Claude
- 可选：自定义 OpenAI Compatible（高级设置）

普通用户只需要：

1. 选择厂商
2. 输入 API Key
3. 选择模型
4. 点击“测试连接”

## 2.6 AI输出过长且直接显示 Markdown 源文本

当前问题：

- 分析过长
- AI经常输出 `**`、``` 等 Markdown 字段
- 阅读体验差
- 无流式响应

v0.2 要求：

- 输出内容精炼
- AI内部仍使用 Markdown
- 前端直接渲染 Markdown
- 支持流式输出
- 禁止显示原始 Markdown 标记

# 3. v0.2 核心产品结构

插件整体分为 3 个一级页面：

```text
CodeVault

├── 主页 / 收藏题库
├── 题目详情
└── 设置
```

# 4. 页面一：主页 / 收藏题库

## 4.1 目标

主页是 CodeVault 的默认管理入口。

用户可以：

- 查看所有收藏题目
- 搜索题目
- 选择题目
- 查看收藏状态
- 快速跳转到 LeetCode
- 进入题目详情

## 4.2 页面结构

```text
┌─────────────────────────────┐
│ 🚀 CodeVault           ⚙    │
│                             │
│ [ 搜索收藏题目... ]         │
│                             │
│ 最近                        │
│ ┌─────────────────────────┐ │
│ │ 最长回文子串      中等   │ │
│ │ 3个解法 · 有笔记         │ │
│ └─────────────────────────┘ │
│                             │
│ 全部收藏                    │
│ ┌─────────────────────────┐ │
│ │ Two Sum           简单   │ │
│ │ 2个解法                  │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

## 4.3 题目点击行为

点击收藏题目：

```text
用户点击题目
      ↓
插件进入该题详情
      ↓
当前 LeetCode 标签页跳转到该题 URL
```

如果当前标签页不是 LeetCode：

- 优先复用已有 LeetCode 标签页
- 如果没有，则打开新标签页

## 4.4 返回

题目详情顶部必须有：

```text
← 返回题库
```

返回后不刷新数据，不丢失列表位置。

# 6. 解法管理

## 6.1 解法名称

每个解法必须支持自定义备注名称。

例如：

- 中心扩散
- 动态规划
- Manacher
- 面试版
- 第一次 AC

默认名称可自动生成：解法 1、解法 2、解法 3。

## 6.2 解法列表

插件中不直接展示完整代码，只展示摘要：

```text
我的解法

中心扩散
Python3 · 2026-09-27
[加载]

动态规划
Python3 · 2026-09-25
[加载]
```

## 6.3 加载解法

点击“加载到页面”后，CodeVault 将保存的代码覆盖到当前 LeetCode 编辑器。

显示轻提示：

```text
已加载「中心扩散」
```

## 6.4 覆盖保护

如果检测到当前 LeetCode 编辑器存在未保存修改：

```text
当前编辑器中有未保存代码。

加载历史解法将覆盖当前内容。

[取消] [继续加载]
```

# 7. 代码捕获

## 7.1 LeetCode 编辑器

用户完成代码后点击“保存当前解法”。

保存：

- 当前题目
- 当前语言
- 当前代码
- 解法名称
- 保存时间

## 7.2 题解区 Hover 捕获

鼠标移动到 LeetCode 题解代码块：

```text
+ 添加到 CodeVault
```

点击后：

- 自动收藏当前题目
- 保存该代码
- 允许填写解法名称
- 标记来源：题解 / 参考

# 8. 笔记系统

## 8.1 核心原则

用户不直接编辑 Markdown。

笔记是：

> 所见即所得的简单富文本笔记

第一版无需复杂富文本编辑器，只支持：

- 普通文本
- 换行
- 图片
- 简单分段

## 8.2 图片

支持：

- Ctrl + V 粘贴截图
- 拖拽图片
- 点击上传图片

粘贴后必须立即显示在笔记中。

禁止：

- 显示 Base64
- 显示图片 Markdown 代码
- 需要额外“预览笔记”

## 8.3 自动保存

建议：

- 输入停止 500~1000ms 后保存
- 页面关闭前保存
- 显示轻量状态“已保存”

# 9. AI 配置

## 9.1 Provider 预设

设置页提供：

```text
AI 服务

○ DeepSeek
○ OpenAI
○ Anthropic Claude
○ 自定义兼容接口（高级）
```

注意：

“Claude Code”是开发工具产品，CodeVault 中应使用 Anthropic Claude API Provider。

## 9.2 普通模式

选择 Provider 后，只显示：

```text
API Key
模型
测试连接
```

Provider 决定默认 API Endpoint，用户无需填写 URL。

自定义 URL 仅放在高级设置。

## 9.3 API 测试

状态：

- 测试中...
- ✓ API连接成功
- 连接失败：API Key无效或模型不可用

## 9.4 API Key 安全

API Key：

- 仅保存本地
- 不上传 CodeVault 服务器
- 默认不包含在数据导出文件中
- 设置页明确提示这一点

# 10. AI 解法分析

## 10.1 目标

AI分析必须短、清楚、可复习。

不要生成长篇教程。

## 10.2 推荐固定结构

```markdown
### 思路
2~4句话说明核心算法。

### 复杂度
- 时间：O(...)
- 空间：O(...)

### 关键点
- ...
- ...
- ...

### 易错点
- ...
```

可选：

```markdown
### 面试表达
1~3句话。
```

## 10.3 输出长度

建议：

- 默认 150~300 字
- 禁止重复代码
- 禁止大段背景知识
- 禁止重新复述完整题目

## 10.4 Markdown 渲染

模型返回 Markdown，前端直接渲染 Markdown。

用户看到的是排版后的标题、列表、代码，而不是原始 `**` 或 ```。

## 10.5 流式输出

AI分析支持 Streaming。

分析过程中提供：

```text
停止生成
```

## 10.6 AI分析保存

生成完成后允许：

```text
[保存分析]
[重新生成]
```

AI分析作为该解法的附属内容保存。

# 12. 插件与 LeetCode 的双向联动

状态应保持一致：

```text
插件选择题目 A
      ↓
LeetCode 跳题 A

LeetCode 用户手动跳题 B
      ↓
插件自动切换到题目 B
```

插件中的当前题目永远跟随当前 LeetCode 页面。

# 13. 数据结构调整

## Problem

增加：

```text
lastOpenedAt
favoriteAt
```

用于主页排序。

## Solution

确认：

```text
id
problemId
name
code
language
source
note
createdAt
updatedAt
aiAnalysis
```

## Note

建议改为块结构，而不是 Markdown 字符串：

```text
Note

problemId

blocks:
- text
- image
```

例如：

```json
[
  {
    "type": "text",
    "content": "中心扩散的核心..."
  },
  {
    "type": "image",
    "assetId": "xxx"
  }
]
```

这样更适合图片直接嵌入显示。

# 17. v0.2 验收标准

v0.2 完成后，用户应该可以完整完成：

```text
打开 CodeVault
↓
进入收藏题库主页
↓
选择一道收藏题
↓
LeetCode 自动跳转
↓
查看自己的多个解法
↓
选择一个解法加载到 LeetCode 编辑器
↓
编辑 / AC
↓
保存为新解法并命名
↓
输入笔记
↓
直接粘贴图片并立即显示
↓
调用 AI
↓
流式获得精炼、已渲染的分析
↓
返回题库
↓
选择下一题
```

整个流程中：

- 不需要登录
- 不需要服务器
- 不需要离开 LeetCode
- 不需要理解 Markdown 语法
- 不需要手动配置 API URL
